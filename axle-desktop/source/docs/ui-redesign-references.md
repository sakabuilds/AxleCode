# Axle main app redesign references

Research date: 2026-10-13. Scope: the existing React/Vite desktop web client in `apps/web`; preserve routes, state, data, provider behavior and existing accessibility primitives. The user explicitly includes existing screens omitted from the brief and excludes requested screens that do not exist.

## Research method and limits

Before implementation, Kroma `kroma_find_ui_inspiration` and `kroma_find_component_code` were called for each screen/component family below. Every image lookup requested Mobbin, Awwwards and Dribbble; every component lookup requested shadcn/ui, Radix UI, Magic UI and Aceternity UI. Additional `kroma_search_design_web` queries repaired overly broad searches and checked specific sources. `kroma_list_sources` verified source names. The recorded research batch contains 56 successful Kroma responses and 16 failed responses, plus later supplemental searches.

Kroma's Serper image/search endpoints were intermittent; `kroma_scrape_site_design` failed. Some successful searches returned zero results or irrelevant results, which were excluded. Direct HTTP checks confirmed the shadcn Sidebar and Resizable documentation and Magic UI Terminal documentation (200); DNS failures prevented direct retrieval from Radix, Aceternity, Linear and Raycast. References below are supported by returned search descriptions and image metadata; this is not a claim that every full reference page was visually inspected. No reference's color palette or source code is copied. Visual QA of Axle is a separate implementation step.

## Direction

Use the compact navigation and quiet information hierarchy of [Linear on Awwwards](https://www.awwwards.com/inspiration/linear-the-issue-tracking-tool-youll-enjoy-using), the product density visible in [Vercel on Mobbin](https://mobbin.com/explore/screens/a8431ea6-da11-414a-9684-7b800cd9620f), and accessible primitive behavior from shadcn and Radix. Axle's treatment is strictly neutral: flat near-black panels, restrained white typography, hairline borders and one composer focus glow. Retain semantic status and diff colors only where they convey meaning. Motion examples are references for restraint and timing, not permission to add decorative animation.

## Explicit exclusions

`/onboarding` redirects to `/`; `OnboardingGate` is a no-op and account onboarding is the current Clerk sign-in gate. Do not invent a new wizard. `/settings/source-control` redirects to general; style the existing source-control content. `/settings/instructions` is real despite being absent from sidebar navigation. Skills exist in composer search and inline chips, not a standalone skills page. The existing file preview is not a full new IDE: do not add a minimap, AI ghost text, or per-hunk accept/reject functionality solely because the brief lists them. Preserve all compatibility identifiers in code and backend contracts while removing legacy product names from visible copy.
